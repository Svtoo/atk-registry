# Scoring notes

Salvaged from the corpus-authoring run before its memories were deleted from the
main Hindsight bank. These are real methodology findings and belong here, not in
a personal memory bank.

## Substring collisions in hard tokens

88 hard tokens across the corpus are substrings of longer hard tokens in the same
memory, for example `--stdin` inside `--stdin-timeout`. A naive "does this token
appear in the fact text" check counts the short one as surviving whenever the long
one does, inflating survival scores.

`scripts/tally.py` matches **longest-first** and drops nested tokens from the
graded set; `read_test.py` reuses its rules so the read side grades the same set.

## Tokens excluded from scoring

Five tokens were deliberately excluded from the scored sets because they occur
inside ordinary prose and would produce false-positive verbatim matches:

    iat   nbf   exp   throws   notes

False positives are the worst failure mode for this eval: it exists to measure
real loss, so a metric that silently rounds up is worse than no metric.

## Corpus generation

Each stratum was generated by a script that asserts every hard token is a literal
substring of its memory text before writing, with a separate `verify.py` pass that
re-reads the written JSON and re-checks all invariants independently.

One substring failure was caught and fixed during generation: `chronyc` output
needed padded column spacing.
